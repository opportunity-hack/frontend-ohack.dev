# ohack.dev hardening plan: security, SEO plumbing, backend reliability (test-first)

## Context

Greg asked for the top improvements for ohack.dev; the audit ranked (1) open backend doors, (2) actively-negative SEO plumbing, (3) backend cache/rate-limit correctness + missing safety net as the top three. He then asked for a focused plan on those three that (a) is validated end to end and does no harm, because several backend shortcuts (auth commented out, permissive uploads, public capability URLs) were deliberate to get code to production and the frontend depends on them, and (b) is test-first: each fix is preceded by a focused regression test that fails today and passes after. Quality over quantity.

Every endpoint proposed for change was traced to its frontend consumers (headers sent, fields read, page auth level), every claim re-verified at source, and the draft plan was then attacked by two independent reviewers (backend, frontend); their corrections are folded in below. Decisions confirmed with Greg: no ohack.dev page is iframed elsewhere; hacker deposits are disabled for the next event (PaymentIntent verification deferred); team-admin fields move to a new admin GET with a frontend fallback.

Repos: FE = `/Users/gregv/dev/fresh_ohack/frontend-ohack.dev` (Next 16 Pages Router, Vercel). BE = `/Users/gregv/dev/fresh_ohack/backend-ohack.dev` (Flask, Fly.io, gunicorn 2 workers × 8 threads, 1 shared CPU).

**Reconciled against merged backend PRs #288 (develop → main) and #289 (stacked hardening) on 2026-09-29.** Already done there and REMOVED from this plan: `teams/<id>/` upload directories are member/admin-gated (`authorize_team_upload_directory`, view-level, `api/submissions/submissions_service.py:253`); `reminders_sent` stripped from public event/list payloads (`_PRIVATE_HACKATHON_FIELDS`); devpost/demo-video membership checks; judging demo video + 3 judging bugs; `sanitize_markdown` scoping; private-repo 404 on `/api/github/activity`. Verified STILL OPEN on `origin/develop`: both decorator-order bugs, newsletter relay, `create-hackathon` PATCH, non-`teams/` upload directories + overwrite, hacker-applications projection, team internals in public payloads, `hash_key` = doc id only (the merged CLAUDE.md sentence "doc_to_json's cache is safe here because DocumentSnapshot.__hash__ includes update_time" is FALSE — the custom key ignores `doc`), judging member resolution (`judging_service.py:216,472` still iterate raw `users`), `get_npo_list` decorator order, no 429 handler, pytest still commented out in CI. ## Ground rules for execution

- **Test first.** For each item: write the test, run it, confirm it FAILS for the documented reason, implement, confirm PASS, run that directory's existing tests. Backend tests run per directory (`ENVIRONMENT=test SLACK_WEBHOOK= SLACK_BOT_TOKEN= <conda py310_ohack_backend_16APR24>/bin/python -m pytest <dir> -q`; whole-tree runs collide on the `tests` package name). **Slack vars must be EMPTY, not dummies**: `send_slack_audit` returns early only on empty and `requests.post("WEBHOOKTHINGTODO")` raises otherwise; the local `.env` has real values, so a "green" run with it may be posting to real Slack.
- **Step 0 in BOTH repos = baseline.** BE: run every test dir with the env above; record failures (memory: certificate_crypto 2, certificate_scanner 1, contact email 1, messages cache_invalidation 1, leaderboard github 2). FE: `npm test` is red today (4 suites / 17 tests: `src/tests/form-scroll-behavior.test.js`, `Blog/__tests__/BlogPage.test.js` [stale strings: placeholder is "Search posts…", link is "View the blog code"], `PrivacyToggle`, `LeadForm`); repair or `test.skip` with a reason before any CI gate.
- **Never block a user flow on a new check that can fail transiently** (fail open with a visible flag).
- **Judging process untouched.** One judging DATA bug (members list empty) is fixed with a test.
- **`api/messages/messages_views.py` / `messages_service.py` are frozen for NEW endpoints.** Fixing decorator order, mapping `None`→404, and stripping fields in existing functions is allowed; the new admin team GET lives in `api/teams/teams_views.py`.
- **Deploy order is part of the design** (see Rollout). Each PR is safe against the other repo's current prod. New FE calls to new BE routes fall back on 404.
